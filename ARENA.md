# ARENA — design decisions

Decision log for the practice arena in `arena/` (branch `arena`). How to use
it: `arena/README.md`. This file avoids spoilers: it does not say which team
plays how, nor what the held-out scenarios contain.

## Ground rules followed

- **Simulator core untouched**: nothing in `src/dme_simulator/*.py`,
  `config/*.yaml` or `builtin_bundles/` was modified. Every match is run by the
  repository's own CLI (`python -m dme_simulator`, i.e. `dme-sim`) as a
  subprocess, with the existing options `--config`, `--agents-dir`,
  `--extra-agent`, `--seed`, `--turns`, `--ui none`, `--record`,
  `--output-dir`, and `--simulations` / `--max-workers` for the `dashboards`
  command.
- **No strategy for the participant's agent**: `src/dme_simulator/agents/` only
  gains `my_agent/agent.py`, the README starter agent copied verbatim. The
  practice report prints facts only.
- Rules taken from README §1.5 and §2, `docs/agent_interface.md`, the configs
  and the code (`simulation.py`, `runner.py`, `loader.py`, `cli.py`,
  `batch_runner.py`, `replay.py`).

## Running matches

1. **One CLI process per match.** The batch mode (`--simulations`) runs seeds
   in parallel but only renders mean-curve PNGs: it reports no per-team final
   cash, so it cannot score a tournament. Each (scenario, seed) match is
   therefore a single CLI run with `--seed`, and the arena runs up to
   `--max-workers` (default: CPU count) of them in parallel — the same seed
   arithmetic as `--simulations` (scenario seed + 0…N-1). The batch mode is
   still exposed as `arena/run.sh dashboards`.
2. **Reading results without touching the core.** Evaluation scenarios set
   `output.progress_interval_turns: 1`, so `--ui none` prints every team's cash
   every turn; the arena parses that output. Practice runs use `--record`
   (the simulator's JSONL with the full per-turn report).
3. **Sealed bids in the practice report.** The recording has units won and
   total spend but not bids or per-material prices. Practice wraps the agent in
   a generated pass-through bundle (`outputs/arena/practice/<run>/instrumented/
   <your folder name>/agent.py`) that loads your class with the repository's
   own loader, logs observation/decision/decide time to `decisions.jsonl` and
   returns the decision unchanged. The team ID is your folder name, so the
   runner seeds your agent's RNG exactly as without the wrapper. Its overhead
   (a few list copies and one file append) counts inside your 100 ms but is far
   below 1 ms. Per-material prices paid and per-product sale prices come from
   your own transactions, which the observation reveals one turn later; for
   the final turn they are reconstructed from your bids/listings
   (pay-your-bid fills your highest bids first), or shown as `~average`.
4. `PYTHONDONTWRITEBYTECODE=1` is set by `run.sh` and the tests, so the arena
   never creates `__pycache__` in an agent folder.

## Opponent field (`arena/opponents/`, spoiler)

- 39 bundles + your agent = **40 teams**, like the real event.
- Composition requested and implemented: **16 weak (41 %), 16 medium (41 %),
  7 strong (18 %)**. Which team is which is only recorded in spoiler files.
- Generated by `arena/tools/gen_opponents.py` from strategy templates with
  per-team randomised parameters (fixed RNG seed → deterministic,
  regenerating changes nothing). The opponents themselves use no randomness.
- Team names are human-looking, hackathon-style names that do not hint at the
  strategy or level. Display replaces `_` with spaces.
- Every opponent file starts with a SPOILER banner.
- Opponents use only the public `Observation`/`GoodsConfig`; several start
  from a price list that a team could derive from the public
  `config/default.yaml`, as real teams could.
- Weak opponents contain logical mistakes only (never invalid actions or
  exceptions), so they always play: a crashing team would just be a free
  rank, which the tests forbid.
- Measured decide time: < 1 ms per decision; the test suite asserts < 50 ms on
  every config for 80 turns.
- Sanity check of the level mix (README starter as "my agent"): strong teams
  take the top places, medium teams the middle, weak teams the bottom; the
  starter lands around 23–25 of 40.

## Scenarios (`arena/configs/`)

- `practice.yaml`: `config/default.yaml` unchanged except the agent directory
  (`opponents`) and output settings (`dashboard: none`, output folder under
  `outputs/arena/`). Same market, 40 turns, seed 42.
- `portal_validation.yaml`: `config/default.yaml` unchanged except output
  settings (no plots, no live dashboard) — plotting costs ~3–5 s and would eat
  the 10 s budget, which the real portal's smoke test presumably does not
  spend on charts.
- `final_1` … `final_4` (spoiler, generated by `arena/tools/make_finals.py`):
  two 40-turn and two 80-turn scenarios, derived from `default.yaml` and
  `scaled_market.yaml` with different seeds, supply, demand and starting
  capital. Goods and recipes are the public ones (assumption: the private
  scenarios varied market conditions, not the product catalogue).
- **8 seeds per scenario → 32 matches per submission** (≈ 20 s on 4 cores).
  `ARENA_SEEDS` overrides the count; `ARENA_TURNS` shortens matches and exists
  for the tests only.

## Scoring and portal

- Per match: rank by final cash, highest first. **Ties get the average of the
  tied ranks; bankrupt teams rank below all solvent teams and their cash is
  shown as 0** — README §1.5 does not cover either case.
- Overall: arithmetic mean of ranks over all matches, lower is better. The
  "final cash" column is the mean final cash over all matches. Equal average
  ranks are listed by mean cash (display order only).
- Only the latest **on-time, valid** submission counts. Rejected uploads are
  recorded in `submissions.csv` but never replace a valid one. Late
  submissions are validated and evaluated (for learning) but marked `late`,
  not counted, and the official leaderboard stays on the last on-time one.
- No clock started → submissions count (a note is printed).
- Validation order and messages follow README §1.5. Details that are not
  published and were chosen here: CPU allowance = 20 s CPU (`RLIMIT_CPU`);
  the 3 validation turns are played with the built-in agents (`DummyAgent`,
  `PatientAgent`, `PriceWarAgent`); the 10 s wall-clock budget is shared by
  the import/construct probe and the 3-turn run; both run with the agent's
  folder as working directory. A folder name already used by an arena or
  built-in team is rejected ("team name taken"), because team IDs must be
  unique in the simulator.
- `.zip` rules: stored/deflate only, no encryption, no links or special files,
  no absolute/traversal/duplicate paths, no nested archives, ≤ 20 MiB
  compressed and ≤ 20 MiB / 64 files extracted, `testzip` must pass.

## Clock

- `arena/.clock` stores the real start time; the display maps it to a virtual
  14:00 → 19:00 day. `clock start` refuses to restart a running clock
  (`clock reset` first).

## State and files

- Per-attempt state lives in `arena/` and is git-ignored
  (`arena/.gitignore`): `.clock`, `submissions.csv`, `submissions/<id>/`
  (validated copy of the bundle, `results.json`, `leaderboard_cash.png`).
  `ARENA_STATE_DIR` relocates it (used by the tests).
- Practice outputs go to `outputs/arena/` (already git-ignored).

## Tests (`arena/tests/test_arena.py`, `arena/run.sh selftest`)

- Uses `unittest` (pytest is not in the locked environment).
- All 39 opponents load, construct and carry the spoiler banner.
- On every config in `config/` and `arena/configs/`, the full field plus the
  starter plays 80 turns through the runner's own timeout and validation
  functions: no timeout, no exception, no invalid decision, slowest opponent
  decision < 50 ms.
- Portal: accepts the starter, an enclosing folder with helpers/models, and a
  ZIP; rejects exceptions, timeouts, invalid actions, wrong return types,
  uncompilable unused helpers, two agent classes, constructor arguments,
  hidden files, bad extensions (including upper-case and `__pycache__`), two
  `agent.py`, bad names, > 64 files, > 20 MiB, non-UTF-8, files outside the
  agent folder, taken names, ZIP traversal/nested/corrupted, wall-clock overrun.
- `run.sh` end to end in an isolated state dir: clock, practice, leaderboard
  before/after submit, valid submit (40-row table + plot), rejected submit,
  late submit not counted, clock reset, and the batch `dashboards` command.
